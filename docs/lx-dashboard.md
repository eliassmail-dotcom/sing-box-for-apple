# sing-box lx++ — Dashboard / «Режим»

## Поведение

Главная карточка «Режим» объединяет выбор стратегии и отображение текущего
маршрута. «Авто • Умный» расположен первым и занимает всю ширину;
четыре остальные плитки — ниже в две колонки.

- **Авто • Базовая**, **Авто • Белые**, **Авто • Полная** и **Ручной режим**:
  зелёная цифра — число *уникальных* узлов выбранной группы, имеющих
  положительный результат URLTest. Вложенные selector/urltest-группы не
  считаются узлами.
- **Авто • Умный**: два счётчика — «Базовые» и «Белые» — отдельно.
  Суммировать их нельзя: узлы могут пересекаться, а белые находятся
  в резерве, пока отвечает хотя бы один базовый.
- Режимы активируются нажатием плитки; синяя рамка отражает **живое**
  состояние селектора `Стратегия` и, при наличии, `Gemini`.
  При ручном изменении одного из селекторов может появляться
  «Смешанная конфигурация».
- Режим «Авто • Умный» доступен автоматически, если профиль содержит
  подходящие группы Базовая, Белые и селектор Стратегия.
  Дополнительного переключателя в настройках LX нет.
  Само наличие резервной группы не включает резервирование:
  оно действует только при выборе этого режима.

## Повторное нажатие: «Сменить узел»

- Нажатие на неактивный режим **выбирает стратегию**, как раньше.
- Нажатие на **уже активный** режим вызывает «Сменить узел»:
  подбирается следующий доступный узел внутри текущей стратегии.
  Текущие селекторы `Стратегия` и `Gemini` не переключаются.
- `Авто • Умный`: команда направляется корневой URLTest-группе,
  которая рекурсивно меняет конечный узел только в выбранной приоритетной
  группе. Пока базовые доступны, в белые переходить **нельзя**.
- `least_test` / `failover`: ядро циклически выбирает следующий узел
  из ответивших на URLTest; стабильный порядок — штрафы, задержка, тег.
  Новый выбор удерживается минимум 30 секунд, если узел остаётся здоров.
  Реальные ошибки и переходы base→white→base обходят это удержание.
- `Ручной режим`: следующий доступный узел выбирается внутри селектора
  `Ручной выбор`, не меняя `Стратегия`.
- `round_robin`: единый узел отсутствует (маршрут выбирается для каждого
  соединения), поэтому команда **явно отклоняется**, а не имитирует
  переключение. Доступность и ошибку показывает интерфейс.
- Если другого живого узла нет, прежний маршрут сохраняется и
  показывается предупреждение. Уже существующие соединения не разрываются.
- Команда использует старый `SelectOutbound` RPC с зарезервированным
  `outboundTag = "__lx_next_node__"` только для URLTest-групп LX,
  что не меняет формат подписки или proto. Нужна соответствующая версия ядра.


## Пункт управления iOS — «Сменить узел»

В `WidgetExtension` добавлен второй независимый Control Widget рядом с
существующим `ServiceToggleControl`:

- **Включить/выключить VPN** — существующий переключатель, не меняется.
- **Сменить узел** — отдельная кнопка `NextNodeControl` с иконкой
  `arrow.triangle.2.circlepath` и своим стабильным `kind`.
- `NextNodeControlIntent` работает без открытия основного приложения.
  При активном VPN отправляет версионированную команду через
  `NETunnelProviderSession.sendProviderMessage`.
- `ExtensionProvider.handleAppMessage` отличает новую команду от обычного
  JSON start options. **Не вызывает reloadService**, не пересохраняет VPN
  и не обновляет подписку.
- Работающая `Стратегия` определяет текущую группу. Для `urltest`
  используется `__lx_next_node__` из нашего ядра; для ручного
  `selector` следующий живой узел выбирается по общему с Dashboard
  алгоритму. `Gemini` не трогаем.
- Если VPN выключен, нет альтернативы или выбран Round Robin, команда
  возвращает осмысленную ошибку. Открытые TCP-соединения не разрываются.
- Отображение статуса Control Center **не обещает смену IP немедленно**:
  уже установленные соединения остаются на старом маршруте.
- Новый control доступен после установки подписанной новой версии IPA
  через Пункт управления → настройка элементов управления → добавление
  элемента `sing-box` → «Сменить узел».

### Проверки перед релизом

1. Убедиться, что в Control Center видны **две** отдельные плитки и они не
   конфликтуют по identifier `kind`.
2. Включённый VPN: повторные нажатия меняют живой узел и обновляют
   «Основной маршрут» на Dashboard, сохраняя режим и Gemini.
3. «Авто • Умный»: пока базовые живы — смена только внутри них; после
   полного отказа — внутри белых; восстановление базовых работает.
4. Ручной режим: смена на следующий узел; отсутствие живых альтернатив.
5. Выключенный VPN / cold start / переход Wi‑Fi → LTE: кнопка не
   запускает VPN и не вызывает внутреннюю ошибку первого старта.
6. Проверить, что обычная `ExtensionProfile.sendProviderMessage` для
   обновления настроек продолжает работать через старую ветку обработки.

## Passive Guard (экспериментально)

В `Настройки → Функции LX → Устойчивость URLTest` добавлен
переключатель «Passive Guard · карантин узлов». Он выключен по умолчанию,
сохраняется отдельно для каждого профиля и меняет **только** временный
runtime JSON, а не файл подписки.

- При включении устанавливается `passive_guard: true` для групп
  `least_test` и `failover`, включая автоматически добавленный
  «Авто • Умный». Группы `round_robin` исключены.
- Карантин после серии независимых отказов действует 60 с, не разрывает
  действующие соединения и при выборе узла не допускает возвращения
  к карантинному серверу по ручной команде.
- Это эвристика надёжности, а не доказательственный детектор ТСПУ:
  отдельный зависший сайт не должен отправлять весь VPN-узел в карантин.
- При старом ядре опция не поддерживается. Перед включением необходима
  сборка с новым `URLTestOutboundOptions.PassiveGuard`.
- После обновления ядра обязательны тесты первого старта VPN и длительных
  соединений, включая YouTube, SSO и переключение между Wi-Fi/сотовой сетью.

## Gemini Chains — локальная сборка из Gemini+

Приложение формирует эффективный Gemini-пул **при запуске VPN**, не
меняя файл подписки и настройки Yandex Cloud Function:

- Единственный исходный пул: Gemini+ (только конечные Gemini-узлы).
  Состав из него берётся с дедупликацией, включая вложенные группы.
- Gemini • Авто — обычные прямые Gemini-узлы.
- Gemini • Super • A — обычные узлы и, если включён тумблер, LX-цепочки.
- Gemini • Выбор — ручной список прямых узлов и цепочек.
- Gemini • Chain • A — URLTest по цепочкам, только при включённом тумблере.
- Каждая цепочка — native LX outbound type=chain с
  outbounds=["Стратегия", "<Gemini+ leaf>"]. Первый хоп выбирается в
  **живой Стратегии** во время дозвона, не запоминается в JSON.
- Gemini Chains в Настройки → Функции LX выключен по умолчанию; при
  выключении Gemini остаётся доступен напрямую через Gemini+.
- Если Gemini+ отсутствует, сохраняется исходная конфигурация, а
  переключатель недоступен. Нельзя включить цепочки без Стратегии.
- Старые генераторные группы, не задействованные Gemini-селектором, пока
  сохраняются ради внешних ссылок; управление активным Gemini полностью
  перехватывает приложение.

Важно: правило DNS/route не изменяется; все existing routes to Gemini
продолжают указывать на Gemini. Трансформация происходит перед общими
health overrides: Passive Guard, adaptive tolerance и min_hold действуют
и на локально созданные URLTest-группы.

Dashboard раскрывает native LX chain в реальные выбранные хопы через
GetRunningConfig + живое состояние групп. При смене Стратегии строка
Gemini меняет первый узел автоматически.

## Профили устойчивости (явный выбор, без скрытой миграции)

В Настройки → Функции LX можно отдельно для каждого профиля выбрать
Стабильный, Баланс, Антиблок или Мои настройки.

| Параметр | Стабильный | Баланс | Антиблок |
|---|---:|---:|---:|
| adaptiveTolerancePercent | 0% | 20% | 35% |
| minHoldSeconds | 60 c | 30 c | 10 c |
| passiveGuardEnabled | false | false | true |
| Подтверждённые сбои | немедленный failover | немедленный failover | немедленный failover |

В Antiблок Passive Guard включает уже реализованные Watchdog,
Quarantine (60 c) и Dial Gate. **Не добавляем новых узлов, групп,
URL-проверок или серверных адресов**: probeURLs наследуются без изменений.
CONNECT_TIMEOUT, SELECTOR_INTERRUPT, DNS, SRS, OpenConnect, priority
base > white и ручной выбор Gemini Chains не меняются.

Выбор пресета выставляет конкретные параметры, а ручная правка этих
параметров переключает название обратно на «Мои настройки».
Ранее сохранённые настройки не мигрируют автоматически.

## Текущий маршрут

Под плитками всегда есть блок «Основной маршрут» и, если профиль содержит
селектор Gemini, строка «Gemini». Они показывают выбранный ядром маршрут,
а не выводят результат случайного speedtest или IP-check:

1. `CommandClient.groups` передаёт живое состояние селекторов/urltest.
2. `GetRunningConfig` по возможности даёт граф outbounds, включая detour.
3. `SelectedOutboundResolver` проходит вложенные группы до выбранного
   конечного узла; для Gemini показывает доступную цепочку `вход → выход`.
4. Пока running config не получен, строится временный граф по живым
   группам *включая листья* (без информации о detour).
5. Подписка на данные запускается при появлении всей карточки, даже если
   информация о выбранном узле ещё не получена.

При использовании Round Robin выбор может зависеть от конкретного
соединения. Отображаемое значение — выбранный/сообщаемый ядром узел
группы, не гарантия, что каждый отдельный поток идёт ровно через него.

## Сохранённые пользовательские настройки

Старые dashboard-карточки `strategyNode` и `geminiNode` удалены
из списка карточек. Если одна из них ранее была включена, а карточка
`strategyMode` — нет, видимость переносится на объединённую карточку.
Порядок прочих dashboard-карточек сохраняется.

## Проверка

- Открыть Dashboard после запуска VPN: названия узлов и пинги должны
  появляться без открытия старых отдельных карточек.
- Изменить основной режим и выбор Gemini в Groups: живой маршрут
  должен обновиться без перезапуска приложения.
- Проверить nested URLTest, ручной выбор, Gemini detour chain,
  отсутствие селектора Gemini, гостевой профиль и неработающие URLTest.
- Проверить миграцию dashboard-видимости со старой версии.
- Проверить повторное нажатие во всех пяти режимах: базовые/белые/полная,
  приоритетная Smart-группа, ручной селектор. Gemini остаётся прежним.
- Проверить 30-секундное удержание, переключение при отказе, отсутствие
  здоровых альтернатив и честную ошибку для Round Robin.
